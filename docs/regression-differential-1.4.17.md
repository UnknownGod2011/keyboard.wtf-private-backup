## Root-cause conclusions so far

1. Not all failures were newly invented: shared recorder arithmetic and Helper page-blocking transport also exist in the reference. Increased use exposed them. Reverting would preserve those defects.
2. Offloading tool work fixed responsiveness but required cancellation/publication checks at every asynchronous handoff. Tests that stopped at coordinator state or result construction missed the send queue, native Helper queue and independent TTS fallback.
3. Local pre-routing and model reasoning can know different things. The contradictory learned-action response is evidence to investigate this boundary; it is not evidence to replace durable memory or hardcode a response.
4. Same prompt/model/audio methods do not prove the same user experience: interleavings and the actual provider output matter. Conversely prompt growth alone is not sufficient cause for an upgrade or rewrite.
5. Real public forms exposed two latent baseline defects: action words inside field labels inflated the verifier's goal count, and native select labels differed from stored values. Current bounded semantic final-field checks and exact selected-state validation fix these without fixture/site rules. Selenium and TestPages/reset/repeat passed with 4/3/3 writes and zero submits.
6. A newer regression is attributable to `973ef70`: suppressing redundant questions from `FieldAnswered` alone also suppressed unknown values when a page had defaults. TestPages then replanned 17 times. Requiring the current plan's explicit expected state through the existing verifier fixed that failure; trailing label punctuation normalization also restored optional skip. The corrected same-task flow asked once, skipped without writing, and completed. This is isolated source/Helper proof, not installed human acceptance.
7. A real Live/registry/Helper run proved active-task routing could override a correct model-selected `open_url`: the URL's colon looked like a value assignment and ordinary page-word overlap admitted the whole unrelated turn as guidance. Rather than extend that grammar, the existing dispatcher now allows only Browser start/control tools into active-task guidance. The repeat opened one direct tab while the same form task stayed paused, then skipped/completed and explained the outcome with one result batch per turn. Immediate local cancellation is unchanged; installed audible proof remains required.
8. Failure contracts matter: local recognizers already catch errors and return empty text. Raw preview recovery handled only exceptions above that boundary. A real-facade empty-result test lost known words before the fix; the existing completion owner now recovers its current cumulative preview and warns about a potentially incomplete tail. No recognition model, audio threshold, command authority or clipboard implementation changed.

Real renderer follow-through: a breakpoint immediately before mutation proved that worker-only cancellation was insufficient—the resumed renderer wrote after its desktop waiter and task lease had ended. The repair now asks the same existing command owner at the actual page boundary, validates sender/tab/frame/command, and protects newer preparation/cleanup. The failing→passing isolated Chromium/native messaging replay also preserves replace/append, repeated radio groups and zero submit/reset. Capability checks reject pre-update workers/content instead of silently claiming this guarantee. This is not installed Store/Jarvis acceptance.

Completion/context follow-through: scalar receipts bypassed acknowledgement, and a 12s cache expiry let an alternate tool escape still-current authority. Tests now retain one result until ordered turn completion/new input. Ordinary transcript observation is read-only: the existing tool dispatcher resolves and executes local actions, so no hidden action can precede a conversational refusal. Immediate cancel/farewell remain local. Bounded Link alias data (no targets; 12 entries/900 JSON characters) and the corrected open_url schema expose the already-supported capability; resolved URLs become follow-up receipts. A compiled-contract developer-Live run chose open_url for two different aliases and explained the returned destination. These are isolated, stubbed-effect model checks plus deterministic ownership tests—not installed audible acceptance.

The second compiled-contract probe forced browser-open failure: both saved aliases still selected open_url once, no success was invented, and “what happened?” accurately explained that no browser opened. Ordinary conversation made no tool calls. No microphone/audio playback/native effect was exercised by these probes. Full source gates: 1,080 desktop/262 backend, Helper scripts and secret scan pass; production EXE/installer/settings hashes and native registration remain unchanged.

Current checkpoint gates: 1,122 desktop, 262 backend and 12 real isolated-staging Firestore tests; Helper reconnect/form/lifecycle, dependency, secret and JavaScript checks pass. Prerecorded long Raw desktop integration is separate from microphone acceptance.
