# keyboard.wtf 1.4.16

keyboard.wtf 1.4.16 is a narrow Jarvis routing and Live rollover reliability
update.

- A completed keyboard.wtf Settings deep link now owns its user turn through an
  authoritative local receipt, preventing a second Browser Automation task from
  trying to satisfy the same request.
- Browser tasks ground an explicitly named, known website or explicit HTTPS
  domain before page interaction. Similar service names and unrelated active
  pages can no longer override that grounded destination.
- Clear corrections to an active browser task supersede planner output that was
  prepared from stale intent. Unrelated Jarvis conversation remains isolated
  from the active browser objective.
- Physical Gemini Live sockets now roll over before the Cloud Run request edge
  timeout, leaving time for close and durable accounting cleanup. Expected
  Firestore cancellation at rollover no longer escapes that cleanup, and the
  desktop visibly reports the brief reconnect instead of remaining in a stale
  Listening state.
- Speech output now pronounces keyboard.wtf as “keyboard dot W T F” and WTF as
  individual letters without changing visible text, URLs, or tool arguments.

The microphone, VAD, playback, barge-in, Smart Writing, billing math, workflows
and durable memory, file search, Screen Reasoning, selected text, Chrome Helper
2.1.25, updater security, and general Browser Automation architecture are
unchanged.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
