# keyboard.wtf 1.4.2

keyboard.wtf 1.4.2 is a focused Windows production-stability update.

- Jarvis enters Listening immediately. A local speech-activity gate and bounded
  PCM pre-roll delay paid Live activation until meaningful speech without a
  visible Vosk transcription step or clipped first words.
- The user-visible Jarvis conversation survives normal provider/Cloud Run
  socket rollovers. Reconnection is speech-triggered, single-flight, bounded,
  and carries a short in-memory conversation digest without persisting it.
- A transient network error no longer erases a valid desktop login. Live
  authentication refreshes and retries once for a 401/403, while confirmed
  revocation still fails closed.
- Settings tabs left open across an app restart recognize only the specific
  stale-session authorization response and reload once to obtain the new
  per-process action token. Existing localhost, same-origin, and CSRF controls
  remain enforced.
- Smart Writing warms the no-cost readiness path while recording and records
  content-free stage timings to make cold-start and model latency diagnosable.
- Voice transcripts are no longer copied into the persistent application log.
- “System default microphone” is now represented explicitly in Settings and
  remains mapped to the current Windows default input instead of being silently
  saved as device zero.
- Chrome Helper diagnostics now distinguish a missing manifest, unsafe
  extension allowlist, missing executable, and registration owned by an older
  keyboard.wtf installation. The published Store helper 2.1.21 remains protocol
  compatible with this desktop release.
- Legacy Cursivis assistant naming is migrated to Jarvis during upgrade.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
