# keyboard.wtf 1.4.17

keyboard.wtf 1.4.17 is a focused Jarvis Live and Browser Automation reliability
update based on production traces from 1.4.16.

- Healthy Live sockets no longer close after thirty seconds of post-turn silence.
  A physical connection uses provider session resumption and context compression,
  with a soft rollover near the provider lifetime that waits for a safe turn
  boundary instead of clipping speech or sensitive tool work.
- Live rollover stays strictly sequential: the old connection closes, settles,
  and releases its slot before one replacement connection starts. Shutdown also
  waits for physical cleanup, preventing stale rollover state, duplicate paid
  sockets, avoidable HTTP 409 conflicts, and misleading Listening state.
- Browser Automation preserves a verified useful or target page instead of
  allowing an older navigation prerequisite to move backward to a less relevant
  page. Final completion is checked against the real visible browser state.
- Child command deadlines remain owned by the child action, so an early action
  timeout cannot be mislabeled as the whole task's five-minute timeout. Planner
  decisions prepared against stale browser state are discarded when the live tab
  has already made verified progress.
- If the paid planner returns malformed or truncated structured JSON, the same
  task makes one bounded planning retry. A second malformed response fails
  safely; valid plans and later execution failures are never retried by this
  guard.

Gemini Live audio/VAD/barge-in behavior, Smart Writing, billing formulas,
workflows and durable memory, file search, Screen Reasoning, selected text,
Chrome Helper 2.1.25, updater security, and the general browser architecture
remain unchanged.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
