# keyboard.wtf 1.4.17

keyboard.wtf 1.4.17 is a narrow Jarvis Live and Browser Automation reliability
update based on production traces from 1.4.16.

- The backend no longer treats thirty seconds of healthy post-turn silence as a
  reason to close a Live socket. Physical Live connections use the provider's
  supported session-resumption and context-compression mechanisms, with a soft
  rollover near the provider connection lifetime and a safe idle-turn boundary.
- A rollover remains sequential: the old provider connection is closed and its
  authoritative usage is settled before the desktop is told to reconnect. This
  prevents parallel paid sockets, duplicate slots, and the avoidable HTTP 409
  race seen during earlier handoffs.
- During a short handoff, microphone input remains in the existing bounded
  activation buffer. The reconnect banner appears only when recovery takes long
  enough to be user-visible, and Listening is restored only after both transport
  setup and microphone readiness are valid.
- Browser Automation now rejects and safely restores an action that unexpectedly
  navigates from a verified useful same-site page to a less specific ancestor.
  Terminal verification also rejects a final page that discarded stronger
  current-task navigation evidence, unless the user actually requested a return
  to the site's home or an earlier state.

Gemini Live audio/VAD/barge-in behavior, Smart Writing, billing formulas,
workflows and durable memory, file search, Screen Reasoning, selected text,
Chrome Helper 2.1.25, updater security, and the general browser planner remain
unchanged.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
