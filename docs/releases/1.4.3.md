# keyboard.wtf 1.4.3

keyboard.wtf 1.4.3 is a focused Jarvis and Smart Writing reliability release.

- Pressing the Jarvis shortcut now immediately opens the real authenticated
  Gemini Live connection. There is no local Vosk or speech-detection gate and
  no second visible startup after the user begins speaking.
- One logical Jarvis conversation now survives recoverable provider and Cloud
  Run WebSocket rollovers. The microphone and single Jarvis surface remain
  active until the user stops the conversation, including through normal
  thinking pauses and silence.
- Live transport closes are recorded with content-free diagnostic metadata so
  reconnect causes can be distinguished without logging audio or transcripts.
- Smart Writing now has bounded request time and exactly one terminal UI path.
  Successful clipboard fallback, failure, cancellation, and timeout can no
  longer leave the Polishing overlay running indefinitely.
- Repeated deterministic tool failures are suppressed, while one bounded retry
  remains available for genuinely transient failures.
- Browser close commands prefer a matching tab when the requested target is a
  web page; the whole browser is closed only when the user explicitly requests
  the browser application itself.
- Explicit user-approved HTTP or HTTPS aliases use the existing learned-mapping
  store and are available to the generic open-target resolver.
- Chrome Helper protocol compatibility remains unchanged. The desktop supports
  the published Store Helper 2.1.21 and the upcoming 2.1.22 package.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
