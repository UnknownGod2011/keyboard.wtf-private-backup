# keyboard.wtf 1.4.13

keyboard.wtf 1.4.13 is a narrow Jarvis startup and durable-memory improvement.

- Paid Live authentication and WebSocket setup now begin alongside microphone
  initialization after the user presses the Jarvis shortcut. The existing
  bounded audio pre-roll, entitlement checks, authentication, stale-session
  HTTP 409 recovery, and user-controlled lifecycle remain authoritative. A
  read-only backend warmup now runs after the persisted account is loaded.
- Explicit durable corrections such as “always” and “from now on” update the
  existing learned app/link/path/browser preference store and are read back
  before Jarvis confirms them. One-time corrections remain conversation-only,
  and an explicit current instruction still overrides a saved preference.
- Saved workflows can be edited in place: actions and aliases may be added or
  removed, actions replaced, and triggers renamed. The one authoritative
  ordered workflow record is written atomically, read back, and re-indexed;
  removed triggers and aliases are tombstoned so old records cannot return.
- The production Live proxy's strict tool allowlist now recognizes the same
  bounded workflow-edit capability exposed by this desktop, while continuing
  to reject unapproved functions.
- Deterministic app/URL/workflow actions remain ahead of Browser Automation.
  A stored web preference opens a normal URL and a saved multi-open workflow
  continues to use direct launch primitives.

Smart Writing, file search, Gemini Live session/rollover architecture, Screen
Reasoning, selected text, Chrome Helper 2.1.25, authentication, billing,
pricing, reservations, and settlement are not redesigned by this patch.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
