# keyboard.wtf 1.4.19

keyboard.wtf 1.4.19 is a narrow real-user reliability update for paused Browser
Automation tasks, selected context, farewell/cancellation ownership, ordered
content verification, and Pricing account presentation.

- A request that explicitly defers browser work until a later user-controlled
  page transition now retains the requested context without starting the action
  early. The later explicit continuation can adopt the fresh active tab while
  keeping one authoritative task.
- Fresh selected or copied context is attached to the browser planner only when
  it belongs to the current turn, or when the user explicitly asked to retain it
  for a later action. A stale unrelated selection cannot satisfy a new task.
- The planner receives the authoritative context before deciding that a form
  value is missing. Optional unknown values remain skippable only when the page
  and user policy allow it; required unknown values still pause safely. Natural
  answers naming one of those requested fields resume the same paused task. A
  page-wide clear/reset control cannot be inferred while correcting one field
  and requires an explicit user request. Complete form-field assignments also
  replace a stale restored value instead of repeatedly appending duplicates;
  explicit append/continue requests retain their additive behavior. Text writes
  carry an explicit replacement/insertion mode; an omitted mode is rejected
  rather than guessed from prose or silently treated as append.
- Chrome Helper 2.1.26 preserves native/ARIA form-question identity and required
  state. Repeated answer labels are scoped to their question, and an unanswered
  required question cannot be hidden by a successful action in another group.
  This is an additive change on the existing 2.1.21 protocol; permissions and
  the native messaging architecture are unchanged.
- Negated or control-only mentions of Browser Automation do not start a browser
  task, even when another clause mentions an interaction or prohibits a page
  action; direct URL/app actions retain authoritative ownership.
- Explicit Browser Automation cancellation clears the intervention/progress UI,
  and a late result from cancelled in-flight work cannot replace the Cancelled
  terminal state.
- A clear Jarvis farewell remains locally authoritative before paused-task
  guidance or model output can consume the turn. The local boundary now uses
  the earliest available provider input transcript because Gemini does not
  guarantee that a finalized transcription precedes the model turn.
- Reading, reviewing, inspecting, or discussing explicitly selected content is
  handled as selected-text reasoning; those comprehension requests do not
  start Browser Automation unless the same turn requests page interaction.
- Durable learned app/link/file/folder mappings now resolve the same exact
  normalized command identity they persisted, including mappings deliberately
  saved with the complete spoken trigger. Exact lookup still outranks ordinary
  app discovery and no fuzzy learned action is executed.
- Requests for latest/oldest/recent content by a named source must establish the
  source collection and verify that the final item identifies that publisher.
- Long Smart Writing requests keep their existing operation deadline and final
  editor behavior, while the shared paid transport envelope no longer expires
  first and incorrectly aborts an otherwise valid long request.
- Pricing waits for the existing Firebase session before rendering its CTA and
  aligns its plan, account notice, and compact FAQ to one responsive container.
- Settings navigation keeps the requested section ahead of later constraints.
  Account usage distinguishes spendable credits from credits reserved pending
  settlement; this is presentation only and does not alter balances or charges.
- Native window closes resolve actual window identities, never Chrome Search
  Tabs. A requested set is closed by handle and verified, with remaining windows
  reported accurately; the Windows shell process is never terminated.
- Direct keyboard actions use balanced native input batches, refuse a changed
  foreground target or already-held user modifier, and share dispatch ownership
  with trusted browser input. They never release user-held modifiers to force
  an action through.
- A multi-action Live tool-call batch returns one combined result while the
  receive loop remains available for farewell and cancellation.
- Valid full-scale negative PCM microphone samples no longer overflow the peak
  meter and drop audio chunks. Capture, VAD and provider configuration are unchanged.
- Browser planner credit-reservation refusals explain the Account & Billing
  limitation instead of reporting an unexpected browser error.

Gemini Live lease/resumption, audio/VAD/barge-in, Smart Writing capture/editor
quality, Raw Dictation, billing math and retention, workflow storage, file
search, Screen Reasoning and updater security are unchanged.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
