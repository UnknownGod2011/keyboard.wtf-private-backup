# keyboard.wtf 1.4.12

keyboard.wtf 1.4.12 is a narrow reliability correction for explicit saved
workflows, capability routing, and spoken conversation dismissal.

- Explicitly remembered workflows now persist one versioned record containing
  the trigger, aliases, and ordered app, URL, and folder actions. keyboard.wtf
  reads that complete record back before confirming it was remembered. A
  completely new Jarvis conversation resolves an exact saved trigger locally
  and executes those durable actions in order; it does not reconstruct the
  routine from temporary conversation context. Deletion tombstones the
  canonical trigger and aliases so stale learned indexes cannot revive it.
- Browser Automation now has an authoritative final capability gate. Opening
  apps or ordinary websites, running a saved multi-open workflow, and preparing
  a supported Gmail draft stay on deterministic app, URL, or direct tools.
  Browser Automation remains available for explicit automation and tasks that
  genuinely require interaction with live webpage state.
- A fresh explicit farewell such as goodbye, bye, go away, stop Jarvis, end
  conversation, end chat, or fuck off now stops microphone capture and
  playback immediately on the first recognized fragment. Provider and account
  cleanup continues asynchronously without waiting for another repetition or
  a provider turn-complete event. Close-tab, close-window, close-app, and
  close-Chrome commands remain normal actions and do not end Jarvis.

Smart Writing, scoped file search, Gemini Live transport and rollover, Screen
Reasoning, selected text, Chrome Helper 2.1.25, authentication, billing,
pricing, reservations, and settlement are not redesigned by this correction.

The installer is not yet Authenticode-signed, so Windows may show an
unknown-publisher warning. Download it only from https://keyboardwtf.com or the
official keyboard.wtf GitHub Release.
