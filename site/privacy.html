Privacy Policy

This policy explains how the keyboard.wtf Windows app and keyboard.wtf Chrome Helper process data when you explicitly ask Jarvis to perform a browser task.

Last updated: July 29, 2026

Local bridgeThe extension communicates with the keyboard.wtf app on your Windows computer through Chrome Native Messaging.

No sale or advertisingBrowser-task data is not sold or used for ads, creditworthiness, or unrelated profiling.

1. Scope and single purpose

The keyboard.wtf Chrome Helper has one purpose: to let the locally installed keyboard.wtf Windows assistant understand and act in Chrome tabs that you explicitly ask Jarvis to control. It supports reading the selected page, finding visible controls, clicking or typing when requested, managing task-owned tabs, verifying results, showing a controlled-tab indicator, and cancelling safely.

The helper is not an advertising, analytics, tracking, credit, or background-browsing product. It does not act on a page when there is no active Jarvis browser task.

2. Information processed for a browser task

Tab and browsing state The active and controlled tab's full URL and title, tab and window identifiers, navigation state, task-owned tab state, and the current domain. To attach to the correct existing Chrome tab, preserve the logged-in session, avoid duplicate tabs, and verify navigation.
Website content A bounded snapshot of visible page text, selected text, page title, and fresh page/control fingerprints. A scan is capped in code rather than collecting a raw full-page DOM dump. To answer page questions, summarize requested content, ground actions, detect page changes, and verify results.
Controls and forms Visible controls such as links, buttons, tabs, inputs, lists, and editors; their role, visible or accessible name, labels, type, enabled/selected/checked state, bounded non-restricted values, safe actions, frame, and on-screen bounds. To choose the correct live control, draw the orange target outline, act on that same control, and confirm the resulting state.
User request and task content The browser task you gave Jarvis and text you ask it to type, summarize, copy, or paste. This may include personally identifiable information or personal communications when you selected a task involving them. To perform the specific task you requested.
Interactions and evidence Task status, actions, target identity and bounds, compact before/after fingerprints, URL or state changes, verification outcomes, retries, cancellation, and concise errors. To prevent stale actions, false success, repeated no-ops, and late actions after cancellation.
Screenshots A screenshot of the controlled tab's visible viewport may be captured when DOM/accessibility information is insufficient, including visual controls, icons, diagrams, or image questions. Optional task evidence may also include a current-viewport capture. For bounded visual recovery and action verification, not continuous recording.

3. Potentially sensitive categories

The helper has broad HTTP/HTTPS page access because users may ask Jarvis to automate a site of their choice. That means a user-selected page can contain sensitive information even though the helper has no specialized permission for that category.

CategoryExact behavior
Health informationNo health-system or health-data permission is used. Health information may be processed only if it is visible in page content or supplied in a browser task you selected.
Financial or payment informationPublic prices, product details, cart state, and other visible page content may be read for a requested task. Password, payment-card, banking, checkout, and order-placement steps are blocked for direct user handling.
Authentication informationThe page title or visible content may reveal sign-in state, account name, or a login prompt. Passwords, one-time codes, CAPTCHAs, and account-security steps are not automated.
LocationThe extension does not request Chrome geolocation. A place, route, address, or other location may be processed when it appears in the page or user request.
Password fieldsThe helper may identify that a password control exists so it can stop, but password values are redacted, excluded from page-state fingerprints, and cannot be typed or clicked by the automation executor.
CookiesThe extension has no cookies permission and does not call Chrome cookie APIs or document.cookie.
Session or authentication tokensThe extension does not read Chrome authentication storage, local/session storage, or cookie tokens. The full current URL is available locally and a site could place a token in that URL or visible page. Before a URL is sent to the AI provider, common token, key, code, signature, password, and session parameter values are redacted. The app cannot guarantee that a site never renders a secret as ordinary visible text.
Files and uploadsThe helper may identify a visible file-input label and type so it can stop. It does not read the selected filename, file path, or file bytes and cannot select or upload a file. File selection remains a manual user step.
Personal communicationsMessages, email text, document text, recipients, or similar content may be processed only when they are part of the page task you explicitly selected. Final sending, posting, publishing, or deletion requires an explicit user request and remains subject to safety checks.

4. How data moves

Chrome Helper to the local Windows app

Task data moves from the Chrome Helper to the keyboard.wtf desktop app through Chrome Native Messaging. The registered native host is restricted to the permanent Chrome Web Store extension ID and the fixed unpacked troubleshooting ID. The native bridge uses a current-Windows-user named pipe; it is not exposed as a public internet service.

Local app to an AI provider

Browser automation in the current release uses the Gemini API key configured by the user in keyboard.wtf Settings. When AI page understanding is required, the desktop app sends the original task, a bounded page-text snapshot, relevant ranked control metadata, recent task evidence, and the redacted page URL to Google Gemini. A current-viewport image is added only for visual recovery. The extension itself contains no API key and does not contact Gemini directly.

If a future release supports another browser-task AI provider, the provider and disclosure must be shown in Settings before that provider is used. The provider's own privacy and retention terms also apply to data sent to it.

5. Storage and retention

  • Chrome extension: the helper does not use Chrome storage, local storage, or session storage to keep a browsing history, page dump, screenshot archive, cookie, or credential.
  • Active task memory: page snapshots, action receipts, prepared text, and screenshots are held in process memory for the active task and are discarded when the task/app lifecycle ends. They are not written as browser workflow memory in this release.
  • Settings: browser-automation enabled state, model choice, and the consent version are stored locally in %LOCALAPPDATA%\keyboard.wtf\settings.json until changed or local app data is deleted.
  • Diagnostics: compact app status and error logs are stored locally in %LOCALAPPDATA%\keyboard.wtf\logs\keyboard.wtf.log. Browser entries can include task IDs, states, a bounded target role/name, outcome flags, lengths, and concise errors, but do not intentionally include full page text, screenshots, cookies, credentials, or typed values. The current release does not automatically expire this log; it remains until you delete the log/local app data or remove it during uninstall.
  • Clipboard: when you request clipboard output, that output remains in the Windows clipboard until you or another application replaces it. Temporary clipboard use for editor paste attempts to restore the prior clipboard after verification.
  • AI provider: retention by Gemini is controlled by the user's Google account/API terms and Google policies, not by the Chrome extension.

6. How data is used and not used

Browser-task data is used only to provide, secure, debug, and verify the browser task the user requested. keyboard.wtf does not:

  • sell browser-task data;
  • use it for personalized advertising;
  • use it to determine creditworthiness or for lending;
  • use it for unrelated profiling, tracking, or purposes unrelated to the Chrome Helper's single purpose; or
  • allow human access except with the user's explicit consent for support, for a necessary security investigation, when legally required, or after data is aggregated and anonymized for internal operations.
The use and transfer of information received from Google APIs complies with the Chrome Web Store User Data Policy, including its Limited Use requirements.

7. Security protections

  • Browser automation is disabled by default and requires a prominent disclosure and affirmative consent before the first task.
  • The native host allowlist contains only the permanent Store ID and the verified fixed unpacked fallback ID; arbitrary extensions and wildcard origins are not allowed.
  • If both helpers are enabled, browser commands fail closed until the user disables one.
  • Tasks use task IDs, stable tab ownership, fresh graph/DOM epochs, live semantic re-resolution, serialized mutations, bounded retries, structured evidence, and cancellation checks.
  • Passwords, file inputs, OTPs, CAPTCHAs, payments, checkout, banking, and account-security steps stay under direct user control.
  • API keys are stored by the desktop app encrypted for the current Windows user and are not included in the extension source or command line.
  • The extension executes only packaged code; it does not download or execute remote extension code.

8. Your consent and controls

  • Review and affirm the browser-automation disclosure in keyboard.wtf Settings before the first task.
  • Cancel a task at any time with Ctrl+Alt+X or the browser-task Cancel control.
  • Disable Browser Automation or withdraw consent in Settings.
  • Disconnect the helper by disabling or removing it from chrome://extensions.
  • Do not enable both the Store and unpacked fallback helpers at the same time.
  • Delete local diagnostics by closing keyboard.wtf and deleting %LOCALAPPDATA%\keyboard.wtf\logs\keyboard.wtf.log.
  • Delete all local keyboard.wtf settings and memories by closing/uninstalling keyboard.wtf and choosing removal of local data, or by deleting %LOCALAPPDATA%\keyboard.wtf. This also removes the saved browser consent setting.

Removing local keyboard.wtf data does not delete information already processed under the independent retention policy of an AI provider.
